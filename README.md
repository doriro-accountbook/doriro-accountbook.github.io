# 카드 가계부 (doriro-accountbook)

카드 소비내역을 월 단위로 적는 **한 화면짜리 가계부**. 구글 로그인 후 Supabase 에 저장한다 — 리로·도리가 같은 장부를 공유한다.

**https://doriro-accountbook.github.io**

## 화면 구성

- **왼쪽 위 년월 선택** → 그 달 가계부를 불러온다. 기본값은 항상 오늘 기준 년월. `‹ ›`로 한 달씩 이동하고, 가운데는 브라우저 월 달력(`input type="month"`)이라 연·월 목록을 코드에 미리 넣어둘 필요가 없다
- **입력 폼** — 카드여부(국민/삼성) · 할부여부(일시불/할부) · 할부 개월수(납부/총) · 일자 · 소비처 · 금액 · 소비주체(리로/도리/공통/일호회사) · 개인사용 입금여부(Y/N) · 입금금액 · 소비상세
- **국민카드(위) / 삼성카드(아래)** 각각의 박스로 분리, 각자 스크롤. 표 안은 할부 블록 → 일시불 순서이고 양쪽 다 **최신이 위**. 박스 아래에 카드별 **일시불 합계 · 총합계(일시불+할부)**
- **맨 아래 월 합계** — 내 돈으로 나간 게 얼마인지 한 줄로:

  **실 카드사용금액 = (국민+삼성 합계) − (개인사용 입금 합계) − (일호회사 합계)**

  개인사용 입금은 리로·도리가 개인 소비를 생활비 통장에 되돌려 넣은 돈이고, 일호회사 합계는 소비주체가 `일호회사`인 행의 그 달 청구액이다. 둘은 따로 집계해서 각각 뺀다

## 입력 규칙

- **일자** — `8/3`처럼 적으면 올해 8월 3일로 자동 변환 (`8-3`, `8.3`, `2026-08-03`, `20260803`도 인식). 📅 버튼으로 달력 선택도 가능
- **금액·입금금액** — 숫자만 입력 가능, 천 단위 쉼표 자동, 원화 표시
- **할부 추가** — 할부여부를 `할부`로 두면 `납부/총` 칸이 나온다. 이번 달에 새로 지른 할부면 `1 / 12`처럼 적는다. 엑셀에서 `2/5`를 적으면 날짜(2026-02-05)로 바뀌던 문제가 여기선 없다
- **할부 금액은 총액으로 적는다** — 100,000원을 5개월로 적으면 그 달 청구액은 **월 20,000원**으로 들어가고, 표에 총액을 같이 보여준다. 개월수를 고치면 월 납부액이 다시 계산된다.
  단, **총액 없이 월 납부액만 있는 행**(엑셀에서 옮겨온 기존 할부)은 그 금액을 그대로 월 납부액으로 쓴다 — 개월수를 고쳐도 금액은 건드리지 않는다
- 나눠떨어지지 않으면 **원 미만은 버린다** (100,000 ÷ 6 = 16,666원). 표의 **금액도 직접 고칠 수 있으니** 카드사가 첫 달에 나머지를 더 붙이는 경우엔 그 행만 고치면 된다
- **소비주체가 리로·도리(개인)일 때만** 입금여부를 선택하고 입금금액을 적는다. 공통·일호회사는 N으로 고정. 표에서 개인 → 공통으로 바꾸면 입금 기록도 같이 지워진다

## 표에서 고칠 수 있는 것

카드값 결제일에 확인하며 고치는 용도라 대부분의 칸을 표에서 바로 누르면 고칠 수 있다 —
**소비처 · 금액 · 할부 개월수 · 소비주체 · 개인 입금 · 입금금액 · 소비상세**.

**일자는 예외로 읽기 전용이다.** 표가 날짜순으로 정렬돼 있어서 일자를 고치는 순간 그 줄이 다른 자리로 튀고,
그러면 이어서 만지는 줄이 방금 고치려던 줄이 아니게 된다. 날짜가 틀렸으면 그 줄을 지우고 다시 넣는 게 안전하다.

## 할부 자동 이월

어떤 달을 **처음 열면** 지난달의 안 끝난 할부(납부 < 총)가 자동으로 들어온다.

- 납부한 개월수 **+1** / 총 개월수, 카드별로 그대로 유지
- 일자는 비우고(매달 청구라 특정일 없음), 입금여부는 새 달이니 N으로 리셋
- 몇 달을 건너뛰어 열어도 중간 달들을 체인으로 만들어 이월한다 (36개월까지)
- 완납(납부 = 총)된 할부는 다음 달로 넘어오지 않는다
- 이미 열어본 달은 다시 열어도 재이월하지 않는다. 이월된 행을 지웠으면 지운 채로 남는다

## 저장

**Supabase** 의 `books` 테이블에 행 하나로 저장한다 (`id = 'doriro'`, 장부 전체가 `data` jsonb 하나).
리로·도리가 **같은 행을 공유**하므로 어느 기기에서 열어도 같은 장부가 보인다.

- **구글 로그인**이 필요하다. RLS 정책이 허용된 두 계정의 이메일만 통과시킨다 —
  다른 계정으로 들어오면 장부가 비어 보이는 게 아니라 권한 없음 안내가 뜬다
- 표를 고칠 때마다 바로 쓰지 않고 **잠시 모았다가 보낸다**. 우측 상단에 `저장 중… / 저장됨 / 저장 실패` 가 뜬다
- 둘이 같은 달을 동시에 고치면 **나중에 저장한 쪽이 이긴다**. 서로 다른 시간에 쓰면 문제없다
- **백업 저장 / 백업 불러오기**(JSON 파일)는 그대로 남겨뒀다. 통째로 되돌리고 싶을 때 쓴다
- 브라우저에 넣는 값은 로그인 세션뿐이다. 장부 자체는 localStorage 에 남지 않는다

`src/lib/supabase.ts` 의 URL·publishable key 는 번들에 그대로 실려 **공개된다**. 원래 공개 전제 키이고
실제 방어선은 DB 의 RLS 정책이다 — 정책을 끄면 주소를 아는 사람이 장부를 읽을 수 있다.

## 실행

```bash
npm install
npm run dev     # http://localhost:5174
npm test        # vitest — 날짜 파싱·할부 이월·합계 로직 테스트
npm run build   # tsc + vite build → dist/
```

로컬에서도 로그인이 필요하다. Supabase 의 Redirect URLs 에 `http://localhost:5174/**` 가 들어 있어야 한다.

## 배포

`main` 에 푸시하면 GitHub Actions 가 빌드해서 Pages 에 올린다 ([.github/workflows/deploy.yml](.github/workflows/deploy.yml)).
손으로 빌드해 올리지 않는다 — 소스와 배포본이 어긋나는 사고를 막기 위해서다.

## 구조

```
src/
  engine/   도메인 타입·순수 계산 로직 (+ 테스트) — 날짜 파싱, 할부 이월, 합계
  lib/      Supabase 클라이언트
  store/    Supabase 읽기·쓰기 (loadBook / saveBook)
  App.tsx   로그인 게이트 + 한 화면 전부 — 년월 선택, 입력 폼, 카드별 표, 월 합계
```
